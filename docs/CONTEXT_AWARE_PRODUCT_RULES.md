# Context-aware product rules

## Golden rule

Onboarding establishes the learner's academic universe. Product modules consume that context instead of repeatedly asking the learner to choose an academic level.

## Exam Simulation

An advanced secondary learner sees only their configured board, qualification, syllabus year/code and enrolled subjects. Primary learners see age-appropriate assessment/quiz modes, not advanced exam controls. Cross-stage or cross-board selection is unavailable from the normal generation flow.

## Learn

Recommendations and generation use the learner context automatically. Subject selectors are limited to enrolled subjects. Curriculum nodes must match the learner's board and syllabus when mapped.

## Profile

Academic context is visible and editable from Profile/Academic Settings. Changes require an explicit confirmation and must not silently delete historical progress. Previous contexts should remain attached to historical attempts where possible.

## Notifications

Notifications are scoped to the user's enrolled subjects and enabled preferences. Academic alerts should deep-link to the relevant lesson, exam, result or Cortex insight.

## Safety against stale context

Context-sensitive caches must include stage, board, qualification, syllabus code/year and subject. Never reuse an exam or lesson generated for a different academic context merely because the topic string matches.
