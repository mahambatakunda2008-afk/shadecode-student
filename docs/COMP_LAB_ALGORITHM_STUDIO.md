# Comp Lab Algorithm Studio

Algorithm work in Comp Lab is a learner-created artifact, not a catalogue of pre-written questions.

## Student-owned workflow

1. Start with a blank pseudocode workspace or an example.
2. Write and edit the algorithm freely.
3. Run it with the real pseudocode interpreter.
4. Inspect output and execution trace.
5. Build a visual flowchart from the algorithm.
6. Add and edit standard flowchart shapes.
7. Create personal test cases, including boundary and invalid cases.
8. Save the draft locally or export/import the project artifact.

## Flowchart conventions

Comp Lab uses recognisable algorithm notation rather than generic rounded cards:

- Terminator: START / END
- Process: rectangular processing step
- Input/output: parallelogram-style data operation
- Decision: diamond decision point
- Directed connectors: execution direction

The visualiser is derived from the student's current pseudocode, but visual editing is an independent artifact so a learner can reason about representation rather than merely decorate code.

## Assessment boundary

Student-created practice can execute entirely in the browser. It must not be described as official examination marking. Authoritative assessment uses protected cases outside the client-controlled environment.

## Future expansion

The next flowchart layer should add explicit branch connectors, connector labels (Yes/No, True/False, Case values), free-form node linking, automatic layout, flowchart-to-pseudocode generation, and consistency checks between the pseudocode and diagram.
