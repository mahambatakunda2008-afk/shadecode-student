# Shadecode Pivot Decision Framework

**Status:** Strategic safeguard
**Date:** 2026-08-16

## Purpose

A pivot should be an evidence-based change in product/customer focus, not a reaction to a difficult week, a failed model call, or temporary frustration.

The purpose of this document is to preserve the reusable technology while giving Shadecode explicit escape routes if the current student-product thesis does not produce sufficient evidence.

## 1. Candidate directions

### A — Shadecode Student

Consumer learning product focused on personalized academic improvement.

### B — Shadecode Cortex

Reusable personalized learning-intelligence infrastructure.

### C — Shadecode Schools

B2B school, teacher, parent, student and learning-intelligence platform.

### D — Exam Intelligence

Focused assessment, past-paper, syllabus and adaptive-exam platform.

### E — Offline AI Infrastructure

Efficient AI systems for low-connectivity environments.

### F — Cortex Developer Platform

APIs/SDKs for developers building educational intelligence products.

### G — Broader Efficient Personalized AI

If the underlying technology proves useful outside education, expand the application domain while preserving the validated Cortex core.

## 2. Evidence dimensions

Track these dimensions consistently:

| Dimension | Question |
|---|---|
| Activation | Do new users reach a useful outcome quickly? |
| Retention | Do users return because the product is useful? |
| Learning outcome | Does evidence show improved capability? |
| Willingness to pay | Does a customer segment value the product enough to pay? |
| Distribution | Can users be acquired efficiently? |
| Technical moat | Is there a capability competitors cannot easily reproduce? |
| Cost | Can the product operate at sustainable unit economics? |
| Reliability | Does the system work under real connectivity/device constraints? |
| Segment pull | Is another customer segment asking for the technology more strongly? |

## 3. Continue criteria

Keep strengthening Shadecode Student when several of these are true:

- students repeatedly return for useful learning
- learning outcomes improve measurably
- personalization outperforms generic tutoring for target tasks
- acquisition/retention has a plausible scaling path
- offline capability creates meaningful differentiation
- the product has a clear willingness-to-pay path

## 4. Focused-pivot criteria

Investigate a narrower pivot when:

- one capability materially outperforms the rest of the product
- exam preparation dominates user demand
- schools/teachers show stronger willingness to pay than consumers
- Cortex infrastructure is requested independently
- offline intelligence creates clear external demand

## 5. Major-pivot criteria

Consider a major change when repeated, well-measured experiments show:

- weak activation despite solving real problems
- poor retention despite iterative product improvements
- weak learning outcomes
- structurally unattractive consumer economics
- another segment has substantially stronger demand
- the underlying technology has value independent of the current product

No single metric should trigger a major pivot alone.

## 6. Pivot preservation rule

A pivot should preserve as much validated work as possible:

```text
Curriculum data
Knowledge model
Assessment engine
Cortex memory
Offline infrastructure
Research results
Security model
Identity/permissions
Content pipeline
Engineering infrastructure
```

The customer and interface can change without discarding the underlying technology.

## 7. Quarterly strategic review

At each strategic review, answer:

1. What evidence improved?
2. What evidence weakened?
3. Which user problem is strongest?
4. Which customer segment is most willing to pay?
5. Which technical capability became more defensible?
6. Which feature consumed resources without producing measurable value?
7. Is the current product thesis still the best use of the accumulated technology?
8. If not, which pivot preserves the most validated assets while improving the opportunity?

## 8. Anti-pivot rules

Do not pivot because:

- an AI provider has a temporary outage
- one feature launched poorly
- a single experiment failed
- a competitor launched a similar feature
- the UI needs another redesign
- growth is slow before activation/retention have been properly measured

## 9. Strategic principle

The goal is not to become emotionally attached to the first product shape.

The goal is to discover the strongest combination of:

**problem × customer × technology × distribution × economics.**

Shadecode Student is the current primary vehicle for discovering that combination.
