# Product Naming Recovery

## Purpose

Recover and implement the student-facing terminology decisions previously established in Shadecode blueprint work. This document prevents reconstructed names from being mistaken for historical decisions.

## Confirmed historical context

- The Design System work included a dashboard direction called **Dashboard Reimagined**.
- That direction treated the dashboard as an **Academic Command Center** and focused it on what the student should do now, progress, forgetting risk, achievement proximity, Cortex recommendations, and exam readiness.
- The broader blueprint corpus is authoritative for historical terminology. Current implementation labels must not silently overwrite blueprint terminology.

## Exact naming decisions

**Status: recovery required.**

The exact blueprint passage containing the replacement names has not yet been recovered from the accessible repository/indexed corpus in this session. No replacement names are invented here.

The following current labels are therefore treated as **legacy/current implementation labels**, not approved final product language:

- AI Lesson Generation
- Exam Simulation
- Math Checker
- Tasks
- Timetable
- Daily Challenge
- Cortex Insight
- Leaderboard
- Achievements / Badges

These labels may be changed only after the historical naming decision is recovered or a new product-language decision is explicitly approved.

## Recovery procedure

1. Search the historical blueprint corpus, especially Design System / Student Evolution material, for terminology and naming decisions.
2. Recover the exact original wording and proposed replacements.
3. Record each decision in a table: legacy label, approved label, source blueprint, rationale, affected routes/components.
4. Update navigation, dashboard, page titles, CTAs, empty states, onboarding, notifications, Cortex surfaces, and other student-facing copy consistently.
5. Preserve internal code identifiers where changing them provides no user-facing value; rename implementation identifiers only when needed for clarity or architectural consistency.
6. Add a decision record if a historical name is superseded by a new owner-approved decision.

## Dashboard requirement

The dashboard redesign must use the recovered product language. Visual polish and terminology are one product experience: the dashboard must be coherent, distinctive, and attractive while remaining faithful to the approved Shadecode language.

## Non-negotiable rule

**Never guess a historical Shadecode name.** If the source cannot be recovered, mark it unresolved and escalate the naming decision rather than laundering a new suggestion into the blueprint history.
