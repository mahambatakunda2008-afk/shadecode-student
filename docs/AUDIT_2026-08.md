# Repository Audit — August 2026

Conducted directly against the live repo and Vercel deployment history, not
from memory or assumption. Every finding below was verified by reading the
actual code and, where relevant, confirmed against production build/deploy
logs. Commit range: `bf26d369..ca0d73b`.

## Bugs fixed

### 1. Task-completion insights were silently no-oping (`d10dee9`)
`src/lib/cortex.js` and `src/lib/cortex.ts` both existed and both exported
`generateInsight()` with different signatures. TypeScript extensions win
module resolution over `.js`, so `import { generateInsight } from
'@/lib/cortex'` always resolved to the `.ts` stub — a placeholder that
returned a throwaway string and never touched the database. No error was
thrown; the real DB-writing implementation in the `.js` file was
unreachable dead code the whole time.

**Impact:** every task completion should have written a row to
`cortex_insights` (read by `Cortex.tsx`, `onboardingRecommendations.ts`,
and `/api/insights/generate`) and never did. Zero errors logged.

**Fix:** ported the real logic into `cortex.ts` as `recordCortexInsight()`,
updated the one call site, deleted the shadowed `.js` file.

### 2. AI provider fallback order violated stated priority (`d0611b1`)
Established priority is Cloudflare (free) → Gemini 2.5 Flash (free) →
OpenAI (unfunded, last resort). The actual code order was Cloudflare →
OpenAI → Gemini → OpenRouter. Since OpenAI is confirmed unfunded (429 in
prod), every single AI call across exam generation, marking, lesson
generation, and math checking was burning a full failed round-trip against
OpenAI — up to the scaled timeout budget — before ever reaching Gemini.

**Fix:** reordered to Cloudflare → Gemini → OpenAI → OpenRouter.

### 3. `gemini-2.0-flash` permanently zero-quota, still being tried (`bc3ec9a`)
All 3 `GEMINI_API_KEY*` env vars share one Google account's quota pool,
and `2.0-flash` is confirmed permanently zero-quota on that account. The
chain still tried it as a second model per key — 3 guaranteed-wasted round
trips any time `2.5-flash` was rate-limited.

**Fix:** removed `2.0-flash` from the model list entirely.

### 4. Timetable save could silently wipe a user's schedule (`ca0d73b`)
`saveSchedule()` in `timetable/page.tsx` did `delete()` then `insert()`
with zero error handling on either Supabase call. If the insert failed
after the delete succeeded (network blip, RLS, validation error), the
user's entire timetable was gone and the UI still showed "✓ Saved."

**Fix:** both calls now check `error`; the save aborts before deleting if
possible, and a visible error message renders if the insert fails after
the delete — no more silent data loss with a false success indicator.

## Regression introduced and fixed within this session

`92c1fed` removed `@emotion/react` and `@emotion/styled` as "unused
dependencies" — they have zero direct imports anywhere in `src/`, but are
official `peerDependencies` of `@mui/material`, pulled in transitively via
`src/theme/MuiThemeProvider.tsx` → `@mui/styled-engine`. This broke
`npm run build` for 4 consecutive production deployments (confirmed via
Vercel deployment history, not assumed). Fixed in `b4fe6d4` by restoring
both packages at their original pinned versions.

**Process gap this exposed:** dependency-usage audits need to check a
package's own `peerDependencies` in addition to grepping `src/` for direct
imports. Direct-import grep alone is not sufficient for any package that
participates in another package's peer dependency chain (styling engines,
UI kits, etc.).

  `HF_API_KEY`, `OPENAI_API_KEY`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`,
  `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`,
  `UPSTASH_REDIS_REST_TOKEN`, `UPSTASH_REDIS_REST_URL`.
  **Status: closed.** `HF_API_KEY` and `UPSTASH_REDIS_REST_TOKEN` are
  confirmed unused anywhere in the current codebase (zero references),

  this app going forward. The Supabase anon key is public-by-design
  (RLS-protected) and not a real secret. Scrubbing git history
  (BFG/`git filter-repo`) was considered and rejected — it rewrites every
  commit hash and would break the 60+ existing branches.

## Minor findings, not fixed (low severity / low confidence of real-world occurrence)

- `src/app/api/exam/mark/route.js`: `totalScore` sums the AI grader's
  per-question `score` directly with no clamp against that question's own
  `marks` value. A hallucinating AI response could in theory push
  `percentage` above 100%. `maxScore` itself is computed safely from the
  server's own question data, not trusted from the AI. Worth a defensive
  `Math.min(r.score, q.marks)` clamp if this is ever observed in practice.
- `src/lib/careers.ts`: `getSupabaseAdmin()` silently returns `null`/`[]`
  if Supabase env vars are missing, with no logging — inconsistent with
  the rest of the app's error-logging discipline. Low practical risk since
  every other feature needs the same env vars.
