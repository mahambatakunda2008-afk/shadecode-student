# DESIGN RULES

## Consistency

Reuse:

- existing components
- spacing system
- typography
- buttons
- cards
- dialogs

Do not create duplicate UI systems.

---

# COMPONENT RULES

Components should:

- have one clear purpose
- be reusable where appropriate
- have clear props
- avoid unnecessary complexity

Avoid:

- massive page components
- repeated markup
- unclear state handling

---

# STUDENT EXPERIENCE RULES

Every screen should answer:

"What should the student do next?"

Provide:

- clear actions
- helpful feedback
- progress visibility

Avoid:

- empty dashboards
- unclear buttons
- confusing workflows

---

# FORM RULES

Forms require:

- validation
- helpful errors
- loading states
- success feedback

Never:

- silently fail
- lose student input

---

# DATA DISPLAY RULES

For information displays:

Prefer:

- clear hierarchy
- summaries
- visual progress
- meaningful numbers

Avoid:

- unnecessary charts
- overwhelming data

---

# MOBILE-FIRST RULES

The application must work on:

- phones
- tablets
- desktops

Check:

- touch targets
- scrolling
- spacing
- keyboard behaviour
- small screens

---

# ACCESSIBILITY RULES

Consider:

- readable text
- keyboard navigation
- contrast
- screen readers
- clear labels

---

# ANIMATION RULES

Animations should:

Improve understanding.

Use for:

- transitions
- feedback
- progress

Avoid:

- excessive movement
- slow interactions

---

# IMPLEMENTATION RULES

When coding:

- use existing styles
- use existing components
- keep changes focused
- avoid unrelated refactoring

If design changes affect many systems:
