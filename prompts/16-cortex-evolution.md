# SHADECODE STUDENT - CORTEX EVOLUTION PROTOCOL

## PURPOSE

Use this prompt when improving, expanding, or rebuilding Cortex.

Cortex is the intelligence engine behind Shadecode Student.

It is responsible for:

- understanding students
- remembering learning history
- making recommendations
- routing intelligence tasks
- powering personalised learning

You must follow:

/prompts/00-master.md

For AI work also follow:

/prompts/04-ai-feature.md

---

# CORTEX OBJECTIVE

Transform Cortex from an AI responder into a learning intelligence system.

Cortex should answer:

"What does this student need next?"

Not only:

"What question did the student ask?"

# CORTEX MODULE RESPONSIBILITIES

Maintain clear separation.

## Router

Purpose:

Decides what intelligence path is needed.

Examples:

Simple question:

→ fast response

Weakness detection:

→ analysis

Study planning:

→ recommendation engine

---

## Memory System

Purpose:

Remember useful learning information.

Possible memory:

- strengths
- weaknesses
- mistakes
- completed lessons
- preferences
- study habits
- goals

Do not store useless information.

Every memory should answer:

"How does this improve future learning?"

---

## Tutor System

Purpose:

Teach.

Should:

- explain concepts
- adapt difficulty
- ask questions
- guide thinking

Should not:

- only provide answers

---

## Teacher System

Purpose:

Analyse progress.

Should:

- identify weaknesses
- recommend actions
- monitor improvement

---

## Scoring System

Purpose:

Measure:

- understanding
- progress
- readiness
- improvement

Avoid meaningless scores.

---

# PERSONALISATION ENGINE

Cortex should understand:

Student profile:

- subjects
- level
- goals

Learning history:

- attempts
- mistakes
- completed work

Current situation:

- upcoming exams
- available time
- workload

---

# DECISION MAKING

Cortex should be able to decide:

Student failed mechanics question.

Possible action:

- explain concept
- provide example
- assign practice
- recommend revision

Student improving rapidly.

Possible action:

- increase difficulty

Exam approaching.

Possible action:

- create revision plan

---

# AI PROVIDER MANAGEMENT

Cortex controls AI usage.

Rules:

Simple tasks:

Use lightweight methods.

Complex tasks:

Use advanced AI.

Always include:

- timeout handling
- fallback
- failure recovery

---

# OFFLINE INTELLIGENCE

Cortex should have graceful degradation.

When AI unavailable:

Use:

- stored knowledge
- previous responses
- local logic
- cached lessons

The student should still receive value.

---

# IMPLEMENTATION RULES

When changing Cortex:

Never:

- create separate AI systems
- bypass Cortex
- duplicate memory logic

Prefer:

- extending existing modules
- improving routing
- improving memory

If architecture changes are required:

STOP.

Explain first.
