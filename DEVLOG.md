## 2026-08-15 — Shadecode 2.0: Assessment Intelligence Contract

Continued the Shadecode 2.0 P0 assessment-intelligence work after auditing the existing Exam Hub and marking pipeline.

**Findings:**
- Exam marking already calculates overall and per-topic scores.
- `topic_mastery` is already the mastery source of truth and is updated after marked exams.
- Exam Hub ingestion already resolves qualification level through `syllabus_papers` and aborts when authoritative mappings are unavailable instead of guessing.
- The existing assessment path is still exam-shaped, while the product roadmap requires assignments, practicals, labs, projects and presentations for tertiary learners.

**Shipped:**
- `docs/ASSESSMENT_EVIDENCE_CONTRACT.md` — canonical, non-persistent evidence boundary.
- `src/lib/assessment/evidence.ts` — normalized `AssessmentEvidence` domain contract with assessment context, question evidence and provenance.
- `src/lib/assessment/__tests__/evidence.test.ts` — coverage for aggregation, impossible-score clamping, tertiary context/provenance and empty assessments.
- `.cortex/tasks.md` — assessment work advanced to the adapter stage.

**Important architectural decision:** this does **not** introduce a new database table or replace `topic_mastery`. Raw assessment evidence remains separate from mastery state. The next implementation slice is an adapter from the current exam-marking result shape into the contract, followed by a field-level audit of persisted `past_papers`, `syllabus_papers` and question data before any migration is proposed.

**Known issue surfaced for follow-up:** the current exam-marking route generates separate random IDs for the Cortex exam-completed event and the persisted `cortex_memory.exam_scores` entry. A stable assessment/attempt identifier should be introduced when the adapter is wired so downstream evidence remains traceable.

**Verification status:** domain tests were added, but the full repository test/typecheck run still needs to be executed before this slice is considered verified/merge-ready.
